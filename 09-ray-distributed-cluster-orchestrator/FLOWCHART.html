◆ Decision 1: Does Pending Task Ratio Exceed Scale-Up Threshold?
src/ray_cluster.py → ClusterAutoscaler.check_capacity()
Condition Evaluated: Monitors ratio of pending submitted tasks to active Ray actor workers across cluster nodes.
↙ LEFT FAST-PATH: YES (High Load)
Provisions additional Ray worker nodes via cloud provider API to increase cluster execution capacity.
↓ DOWN EXECUTION: NO (Optimal)
Proceeds to step 2 execution: Dispatch Task to Idle Ray Actor.
◆ Decision 2: Are Idle Workers Present with Zero Task Load for > 300 Seconds?
src/ray_cluster.py → ClusterAutoscaler.evaluate_scale_down()
Condition Evaluated: Audits idle worker node duration to scale down unnecessary cloud compute instances.
↓ DOWN SUCCESS: YES (Scale Down)
Dispatches task to Ray actor worker, executing zero-copy memory reads against shared Plasma store.
↘ RIGHT BRANCH: NO (Maintain)
Triggers exception evaluation to check retry boundary limits.
◆ Decision 3: Does Worker Count Exceed Minimum Static Baseline?
src/ray_cluster.py → ClusterAutoscaler.get_min_workers()
Condition Evaluated: Ensures cluster does not scale down below minimum configured static worker node count.
↺ UPWARD RETRY LOOP: YES: Terminate Worker
Gracefully drains active task references from target worker node before triggering termination.
↓ EXHAUSTED FALLBACK: NO (Keep Stable)
Terminates excess idle worker nodes, reducing cloud infrastructure billing costs.
