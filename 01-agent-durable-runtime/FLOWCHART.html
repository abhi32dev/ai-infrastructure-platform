⚡ Exhaustive Logical Conditionals & Codebase Mapping
Decision 1: Is Step Idempotent & Already Executed?
src/agent_runtime.py -> StateStore.get_active_state()
Rule Evaluated: Queries SQLite WAL event log for existing step_id checkpoint.
✔ LEFT BRANCH (Cache Hit): Replays cached state output directly without re-executing external tool calls ($0 computation).
✖ RIGHT BRANCH (New Step): Proceeds to invoke external tool function within exception boundary.
Decision 2: Did Tool Invocation Succeed?
src/agent_runtime.py -> DurableAgentRuntime._invoke_tool()
Rule Evaluated: Evaluates return payload for unhandled exceptions, null pointer responses, or runtime errors.
✔ LEFT BRANCH (Success): Atomically writes step checkpoint to SQLite WAL and updates active step pointer.
✖ RIGHT BRANCH (Error): Triggers exception handler and evaluates retry budget allocation.
Decision 3: Is Retry Counter < Max Retries (3)?
src/agent_runtime.py -> DurableAgentRuntime.rollback_to_step()
Rule Evaluated: Checks active retry counter against maximum threshold of 3 bounded attempts.
✔ LOOP UP (Retry): Rewinds SQLite transaction to last valid checkpoint state and re-queues tool execution.
✖ DOWN BRANCH (Exhausted): Pauses workflow state machine and escalates step to Human-in-the-Loop (HITL) approval queue.
